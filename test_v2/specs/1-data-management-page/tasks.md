- 描述中需包含精確的檔案路徑

## 階段 2: 基礎建設 (前置工作)

**目的**: 建立所有使用者故事都依賴的核心基礎設施，必須在任何使用者故事開始前完成。

- [x] T002 在 `index.html` 中，設定主要的 HTML 文件結構 (`<!DOCTYPE>`, `<html>`, `<head>`, `<body>`)，並連結 `css/style.css` 和 `js/app.js` 檔案。
- [x] T003 在 `index.html` 中，建立頁面的主要佈局，包含一個用於「新增紀錄」表單的容器、一個搜尋框容器，以及一個資料表格容器。
- [x] T004 在 `css/style.css` 中，應用藍色與黃色的主要配色方案，並為主要佈局元素 (如 body, containers) 設定基礎樣式。
- [x] T005 在 `js/app.js` 中，建立一個資料存取層 (DAL)，包含與 `localStorage` 互動的函式，應至少有 `getAllRecords()` 和 `saveAllRecords(records)`。
- [x] T006 在 `js/app.js` 中，建立一個 `renderTable(records)` 函式，此函式接收一個紀錄陣列，並在其容器中繪製出 HTML 表格。
- [x] T007 在 `js/app.js` 中，設定一個 `DOMContentLoaded` 事件監聽器，以便在頁面載入完成時，從 `localStorage` 取得初始資料並渲染表格。

**檢查點**: 基礎建設完成 - 現在可以開始實作使用者故事。

## 階段 3: 使用者故事 1 - 新增資料 (優先度: P1) 🎯 MVP

**目標**: 允許使用者在系統中新增一筆紀錄。

**獨立測試**: 使用者可以填寫表單，點擊「新增」，並看到新紀錄出現在表格中。刷新頁面後，資料應仍然存在。

### 使用者故事 1 的實作

- [x] T008 [US1] 在 `index.html` 中，建立用於新增紀錄的 HTML 表單，包含「編號」、「姓名」、「單位」的輸入框，以及一個「新增」按鈕。
- [x] T009 [US1] 在 `js/app.js` 的資料存取層中，實作 `addRecord(record)` 函式。它應讀取現有紀錄，加入新的一筆 (使用 `crypto.randomUUID()` 產生內部 ID)，然後將更新後的陣列存回 `localStorage`。
- [x] T010 [US1] 在 `js/app.js` 中，為「新增」按鈕添加事件監聽器。此監聽器應讀取表單輸入值，呼叫 `addRecord()`，然後用更新後的資料重新渲染表格。

**檢查點**: 使用者故事 1 應可完全獨立運作並通過測試。

---

## 階段 4: 使用者故事 2 - 查詢與檢視資料 (優先度: P2)

**目標**: 允許使用者過濾表格中顯示的紀錄。

**獨立測試**: 使用者可以在搜尋框中輸入文字，表格應動態更新，只顯示符合條件的紀錄。

### 使用者故事 2 的實作

- [x] T011 [US2] 在 `index.html` 中，於表格上方新增一個搜尋輸入框。
- [x] T012 [US2] 在 `js/app.js` 中，為搜尋輸入框添加事件監聽器 (例如 `input` 事件)。
- [x] T013 [US2] 搜尋事件監聽器應從資料存取層取得所有紀錄，根據搜尋關鍵字過濾它們（比對所有欄位），然後用過濾後的結果呼叫 `renderTable()`。

**檢查點**: 使用者故事 1 和 2 皆應可獨立運作。

---

## 階段 5: 使用者故事 3 - 修改與刪除資料 (優先度: P3)

**目標**: 允許使用者編輯和移除現有的紀錄。

**獨立測試**: 使用者可以點擊「刪除」來移除一筆紀錄，或點擊「修改」來直接在表格中編輯其內容。

### 使用者故事 3 的實作

- [x] T014 [US3] 在 `js/app.js` 的 `renderTable()` 函式中，為每一橫列添加「修改」和「刪除」按鈕，並在橫列或按鈕上包含一個對應紀錄唯一 ID 的 `data-id` 屬性。
- [x] T015 [US3] 在 `js/app.js` 中，為表格容器添加一個單一的事件監聽器，以處理「刪除」按鈕的點擊事件（使用事件委派）。
- [x] T016 [US3] 「刪除」事件處理器應從 `data-id` 屬性中識別紀錄 ID，呼叫資料存取層中一個新的 `deleteRecord(id)` 函式，然後重新渲染表格。
- [x] T017 [US3] 在 `js/app.js` 中，擴充表格的點擊事件監聽器，使其也能處理「修改」按鈕的點擊。
- [x] T018 [US3] 「修改」事件處理器應將被點擊的橫列切換為可編輯狀態 (例如，將 `<span>` 標籤替換為 `<input>` 欄位)，並將「修改」按鈕變為「儲存」按鈕。
- [x] T019 [US3] 「儲存」事件處理器應從輸入欄位中讀取新值，呼叫資料存取層中一個新的 `updateRecord(id, updatedData)` 函式，然後重新渲染表格以顯示儲存後的資料。

**檢查點**: 所有使用者故事現在都應可獨立運作。

## 依賴關係與執行順序

- **階段 1 (環境設定)** 必須最先完成。
- **階段 2 (基礎建設)** 依賴階段 1，並阻擋所有其他階段。
- **階段 3, 4, 5 (使用者故事)** 可在階段 2 完成後以任何順序實作，但建議遵循 P1 -> P2 -> P3 的優先級順序。
- **階段 6 (優化)** 可在基礎建設完成後隨時進行，但最好留到最後。

## 實作策略

我們將遵循漸進式交付模型：

1.  **基礎**: 完成階段 1 和 2。
2.  **MVP**: 完成階段 3 (使用者故事 1)。此時，新增和檢視資料的核心功能應已可用。
3.  **擴充查詢**: 完成階段 4 (使用者故事 2)。
4.  **擴充編輯**: 完成階段 5 (使用者故事 3)。
5.  **最終優化**: 完成階段 6。
